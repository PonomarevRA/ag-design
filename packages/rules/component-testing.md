# Проверка компонента после изменения

**Обязательный порядок AG после добавления или изменения компонента.** Агент запускает целевые функциональные и lifecycle-тесты компонента, проверку его реального preview-контракта и релевантный сценарий производительности. Регистрация метаданных, генерация теста и чужой старый PASS не являются запуском. Пример должен предоставлять element, interact() и dispose(); асинхронные interact/whenIdle ожидаются. Проверяются ошибка взаимодействия, освобождение после ошибки и продолжение следующего компонента. Для подключаемой библиотеки запускается её пакетный сценарий, а не фиктивный core preview.

Сохраните фактический результат с ID/версией компонента, сценарием, окружением и ограничениями через design_record_performance, затем прочитайте design_performance. Для допуска отдельно используйте design_report_checks с актуальным контрактом и требуемыми доказательствами. Ошибка получает outcome=failed, этап и сообщение; отмена — cancelled; выполненный замер — measured. Сохранение отчёта не запускает код и не квалифицирует компонент. Если выполнить проверку нельзя, укажите причину и unknown/blocked, не PASS.

Heap / экземпляр означает удерживаемую JS-память живого экземпляра при явно указанном методе. Браузерные времена DOM/CSS и Node/jsdom с GC — отдельные строки; общий heap процесса, RSS, GPU и память компонента не взаимозаменяемы. Отрицательная медиана GC не превращается в ноль. «Время измерено; память не измерена» описывает отсутствие метрики, а не ошибку компонента. Переносимый CLI: node --expose-gc tools/benchmark-memory.mjs --component ID --instances 40 --output /absolute/path/report.json. Данные CLI остаются экспериментом Node/jsdom, не browser/AT-проверкой.
