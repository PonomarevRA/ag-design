# Illustrated user book

User chapters read as articles: context, takeaway, a meaningful example, source-backed explanation and a small practice task. User prose is authored RU/EN; compact English agent instructions remain separate. New examples are AG teaching material, not quotes or independently validated product results.

Optional section `lesson` contains `group` (start/interface/inclusion/communication/delivery/system), literal takeaway/scenario/before/after text, one to five practice steps and `figure:{kind,labels}`. The bounded local renderer inventory is flow, structure, spacing, typography, actions, form, states, color, data, slide, workbook, journey, languages and compare. Two to six literal labels describe the figure. Never accept HTML, scripts, imported URLs or executable renderer names. Translated editions may supply their own lesson. The current source hash includes source teaching metadata; stale translations cannot override it. Legacy/custom chapters without lessons retain prose rendering.

Detail user responses include only the selected edition's lesson. User list responses retain the small learningGroup; compact agent list/detail omit complete lessons. Do not reintroduce full translated dictionaries into agent results.

Meaningful diagrams have nearby textual explanation. Quantitative figures use fixed illustrative data, explicit units and an exact table. Live component examples use actual package factories and isolated contexts; they do not persist user preferences or register real usage. Explanatory examples and intentional before/after contrasts are labelled. They are not actual customer results, exported PPTX/XLSX files or production qualification.

Reader chrome preserves host palette, existing chapter identities, search, selected chapter, locale/fallback and async response fences. Disposing a chapter releases owned component examples, observers and listeners; disposing the reader leaves the host locale runtime intact. Sources remain available, while agent tooling details belong in a disclosure after the article. Keep article headings, keyboard focus, long names, narrow layout, text growth and print readable.

Editorial basis: [W3C complex images](https://www.w3.org/WAI/tutorials/images/complex/) for adjacent explanations and structured alternatives. Text sizes, reading-column width, chapter groups and practice format are authored AG defaults, not normative measurements attributed to W3C.
