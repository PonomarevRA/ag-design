# Геометрия и слои AG

Эти числа — исходные продуктовые токены AG для плотных desktop/web-интерфейсов. Они не выдаются за универсальные размеры Apple, Material или критерии WCAG. Нативные points, Android dp/sp и CSS px нельзя механически считать одной физической величиной.

| Назначение | Стартовый токен AG | Когда менять |
|---|---|---|
| Шаг | 4 CSS px | оптическое выравнивание и реальные ограничения записываются как исключение |
| Внутри группы | 4/8/12 px | плотность, длина labels, touch |
| Между группами | 16/24/32 px | читаемость и размер рабочей области |
| Поле/кнопка | min-height 32 px | больше при крупном тексте; не обрезать содержимое |
| Coarse pointer | target 44 CSS px | отдельно проверить платформенный минимум и WCAG-исключения |
| Иконка | 20 px | оптическая масса, без изменения области нажатия |
| Радиус controls/panel | 7/12 px | профиль формы не должен скрывать focus |
| Rail/обычная панель | 52/220 px | сложный контент и выбранная пользователем ширина |
| Текст desktop | 13 px base, 12 px secondary | продолжительное чтение требует крупнее, 200% текста обязательно проверить |
| Заголовок | 15–17 px section, 22–25 px page | не повторять одно название в нескольких полосах |

## Группировка

Сначала один сценарий и иерархия, затем общая ось, пробел и размер. Только после этого рамка, фон и тень. Межгрупповой интервал больше внутреннего. Вместо трёх вложенных карточек используйте секции с заголовком и пробелом, если принадлежность понятна. В плотном канбане ключ/статус и роль/языки — компактные группы, полная история открывается в деталях.

## Порядок поверхностей

Локальная модель слоёв AG: `content → sticky-controls → popover → modal`. Это семантический порядок, не нормативная таблица z-index. Реализация назначает именованные уровни и проверяет stacking context; большое число z-index само не исправляет clipping. Tooltip связан с инициатором, не перехватывает обычный ввод. Modal имеет собственный focus scope, Escape/закрытие и возврат фокуса. Popup чата не превращает весь продукт в модальное окно.

Прозрачность используется для разделения контекста, а не фоном каждого блока. Для reduced transparency/increased contrast нужен читаемый вариант. Не воспроизводите «Liquid Glass» blur-эффектом на всех карточках: текущая HIG различает control layer и content layer. Сложные визуальные материалы требуют проверки настоящей платформы.

## Принятие исключения

В описании компонента укажите сценарий, изменённый токен, почему стандарт не подходит, проверенные viewport/text sizes/input modes и оставшиеся ограничения. Исключение не меняет остальные компоненты автоматически.

Источники: [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout), [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [Android Grids and units](https://developer.android.com/design/ui/mobile/guides/layout-and-content/grids-and-units), [WCAG Target size minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

## Вложенные и соседние скругления Apple

Fixed, capsule и concentric имеют разные роли. Для равномерного inset круговых дуг: R_inner=max(0,R_outer-inset), ограниченный размерами внутреннего элемента; вне контейнера нужен fallback. Это частный web-контракт AG, не общий алгоритм Apple для arbitrary/continuous corners. Соседние элементы согласуются по роли и ритму; они не становятся концентричными только из-за соседства. В плотных Mac-панелях Apple сохраняет rounded rectangles у малых controls, а capsule использует для крупных/акцентных.

Источники: https://developer.apple.com/videos/play/wwdc2025/356/ ; https://developer.apple.com/documentation/swiftui/edge/corner/style/concentric .
