# Выбор иконки и подписи команды

Авторская рекомендация AG · rules0.9.1 · 2026-10-26. Применяется к новым интерфейсам и ревью существующих. `icon-only` обозначает представление настоящей кнопки, а не кликабельную картинку. Для перехода по адресу сохраняйте ссылку.

| Условие | Предпочтительный вариант | Причина |
|---|---|---|
| Знакомый аудитории символ, ясный объект, частое действие в стабильной панели | Icon-only, обычно quiet | Быстрое распознавание и компактная панель |
| Символ помогает найти действие, но подпись добавляет смысл/объект | Иконка + короткий текст | Сохраняются поиск взглядом и понятность |
| Предметная команда, непривычная операция, важное разрешение или неоднозначные последствия | Видимый глагол + объект; иконка необязательна | Смысл нельзя переносить целиком в hover |
| Редкая вторичная команда | Подписанный пункт overflow | Уменьшает постоянную нагрузку панели |
| Выбор режима или представления | Именованные сегменты/табы/выбор с текущим состоянием | Это выбор состояния, его нужно видеть |

Частота сама по себе не делает символ узнаваемым. «Копировать» у конкретного блока может быть понятным; такая же картинка в общей шапке не объясняет, что копируется. Для экспертов допустима более плотная панель после проверки, но не предположение об универсальности значков. Нет фиксированного допустимого процента icon-only команд.

## Алгоритм решения

1. Назовите действие, объект, аудиторию и последствия. Частое/редкое и основное/вторичное — разные свойства.
2. Найдите знакомый символ для этого действия именно в этом контексте. Если смысл без hover неоднозначен, оставьте текст или icon+text. Не подбирайте абстрактный символ только ради узкого места.
3. Выберите акцент независимо от подписи. Вспомогательный icon-only обычно quiet; главное действие должно оставаться заметным. Видимый текст — исходный выбор для значимого шага AG, но знакомая кнопка отправки в явно оформленном composer может быть иконной при проверенной понятности. Значимые разрешения и необратимые последствия требуют видимого текста.
4. Уточните groups/padding, короткие подписи, перенос и редкие команды. Не убирайте essential действия в меню только ради плотности. Не уменьшайте hit target до рисунка.
5. Передайте локализованное имя/состояние и проверьте обычный, узкий, keyboard и touch сценарий. Если распознаваемость не проверена, отметьте её unknown и предпочитайте текстовый fallback.

## Применение к чатам

| Текущее действие | Рекомендация | Ограничение |
|---|---|---|
| К последним | Icon-only: стрелка к нижней границе ленты, возможен счётчик новых | Не путать с download; имя «К последним сообщениям», видимый счётчик не заменяет имя |
| Загрузить историю | История/часы + «Ранее» или «Загрузить историю» | Стрелка вверх часто означает только прокрутку. Icon-only допустим после проверки устойчивого паттерна |
| Очистить видимое | Обычно подписанное «Очистить видимое» в overflow; в частом expert-сценарии допустим понятный символ очистки | Корзина может обещать удаление сохранённой истории. Необратимость не выдумывается: здесь очищается только окно |
| Подтвердить / Отклонить | Сохранить текст; конкретизировать действие и объект, если контракт позволяет | Галочка/крест не объясняют полномочия и последствия; акцент не должен автоматически склонять к разрешению |
| Продолжить ответ | Видимая подпись либо иконка + текст | Play/refresh могут означать запуск агента, повтор запроса или повторную отправку |
| Обрыв / восстановление | Подписанные состояния/сценарий демонстрации | Это demo control; спрятать в именованную группу сценариев, а не смешивать с действиями диалога |
| Другая сессия | Именованный выбор сессии или текстовая команда | Случайная иконка switch не раскрывает, куда произойдёт переход |
| Диалог / операции | Два подписанных сегмента с выбранным состоянием | Изменение внешнего вида кнопки не исправляет отсутствующий padding контейнера |
| Настройки, закрытие, развернуть | Знакомые icon-only в контекстной группе | Имена, hover/focus/pressed/busy, явное восстановление размера и сохранённая область нажатия |

Согласованные пользователем цветные кружки не меняются данным советом. Эта таблица не изменяет реализацию и не заменяет проверку реального чата.

## Доступность, состояние и адаптация

- Реальная кнопка работает Enter/Space, имеет видимый focus и имя действия через label/aria-label/aria-labelledby. Декоративный SVG не получает отдельный фокус. Имя, tooltip и состояние локализуются одним RU/EN контекстом; ID команды стабилен. Accessible name сам по себе не доказывает узнаваемость символа.
- Tooltip помогает вспомнить действие. В web один `title` не доказывает доступность клавиатурой или на touch. Custom hover/focus content проверяется на dismissible, hoverable и persistent по применимым условиям WCAG1.4.13. Native browser title является отдельным исключением этого критерия, а не общей гарантией качества. Для touch нужен понятный контекст, видимый текст или подписанное меню; long-press не предполагается без реализации/проверки.
- У toggle сохраняется стабильное имя с aria-pressed и видимым состоянием. Если команда меняет глагол «Развернуть / Вернуть размер», обычная кнопка с актуальным названием может быть яснее; не совмещайте механически оба паттерна. Для выбора представления предпочтителен явно выбранный элемент. Цвет не единственный признак состояния.
- AG defaults: рисунок20px, компактная цель32px, coarse-pointer44px; это стартовые токены продукта. WCAG2.5.8:24×24 CSS px либо применимое исключение/spacing. Размер glyph, видимой рамки и hit target проверяется раздельно. Retina/zoom не оправдывают слишком маленькую CSS-цель.
- На320 CSS px и200% текста сохраняйте смысл, порядок, цели нажатия и доступность основного действия. Исчезновение подписи по breakpoint требует текстового fallback и проверки context/touch. Тихая иконка не должна прилипать к краю: отступы задаёт группа.
