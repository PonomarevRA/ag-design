# Переиспользуемые паттерны компонентов 0.2

## Контекстная шапка и панели

`bindWindowShell` переносит настоящие DOM-кнопки, сохраняя слушатели, а не создаёт вторую бизнес-логику. Шапка показывает название выбранного раздела; для открытой задачи/сущности — её заголовок. Постоянное имя продукта остаётся в системном меню/доступной идентичности. Частые команды (создать, обновить, настройки) помещаются в шапку; редкие — в overflow. Назад/вперёд идут после системных оконных кнопок перед переключателем меню, отражают реальную историю продукта и недоступны при отсутствии перехода. Atlas сохраняет выбор проекта. Причина: одна строка контекста и действий оставляет больше места содержимому. Альтернатива: отдельная page toolbar в браузере/ОС без нативной поддержки. Ограничение: сложный workflow и поиск не следует скрывать в icon-only кнопках без подсказки.

Нативный macOS адаптер использует публичные NSWindow/NSToolbar/NSTitlebarAccessoryViewController; системные traffic lights остаются настоящими. HTML fallback скрывается **только после подтверждения native-window-commands**. Канал уведомлений принимает null из собственного main frame; native сам читает фиксированный набор bounded полей. Произвольные URL, команды и JS через канал не передаются. На Windows/Linux доступен тот же web toolbar; нативную реализацию нельзя считать проверенной без запуска на ОС.

`bindResizablePanel` размещает разделитель на внутреннем краю: у левого меню справа, у правого слева. Drag и ArrowLeft/Right (Shift — крупный шаг), Home/End изменяют ширину с ограничениями, ARIA separator объявляет диапазон. Сохранение локальное и опциональное; свернутая рейка не прыгает на другую сторону и не наследует expanded width. `dispose()` освобождает pointer/resize listeners. Содержимое сохраняет минимум доступной ширины. Не создавать пустую правую панель ради симметрии.

## Мини-чат действий агентов

`createAgentActivityChat` — компактный popup справа снизу, по умолчанию закрытый. Есть раскрытие/сворачивание, закрытие с возвратом фокуса и отдельное opt-in для маркеров. Строка содержит agent, task, **request и response**, статус. Текст вставляется буквально; очередь ограничена (50 по умолчанию, максимум 500), большие поля явно обрезаются, число вытеснений показывается. Компонент не опрашивает сервисы: транспорт/подписка, корреляция задач и авторизация принадлежат приложению. Причина: активность доступна по требованию и не занимает постоянную колонку. Альтернатива: полноэкранный журнал для расследования; popup не заменяет архив.

## Связи карточек Atlas

`connectionControls`/`connectionCurve` повторяют геометрию `code-atlas/web/edge-curves.js`: касательные на 1/3 и 2/3, направления horizontal/vertical/direct; offset смещает оба control points. `createCardConnections` строит SVG по существующим Map<id,HTMLElement> и явным edges {from,to,kind,label}; стрелка показывает направление, related — пунктир. Неизвестные концы пропускаются и считаются, связи не выдумываются. Есть отдельный доступный список переходов. ResizeObserver следит только за использованными карточками; после pan/zoom приложение вызывает update. Не более 200 связей на слой; идентификаторы markers уникальны. Dispose удаляет observer/слой/список.

Причина: одинаковая пространственная модель отношений для графа кода и задач; выбор узла остаётся в продукте. Альтернативы: список зависимостей для клавиатуры/маленьких экранов, специализированный canvas для больших графов. Ограничения: **не** полный Atlas edge-routing (обход препятствий, bundling, группировка, камера), не автокомпоновка. Не копировать renderer целиком ради небольшого графа. Нагрузку проверять на реальной плотности и масштабе.

## Рабочая доска графа

`createBoardViewport({viewport,scene,storageKey,onChange})` управляет одной сценой в CSS-пикселях. Продукт владеет данными, расположением карточек и связями. Камера не меняет положение карточек друг относительно друга. Связи вычисляются в координатах сцены: разность экранных прямоугольников делится на текущий scale; перемещение всей сцены не требует перестроения линий.

Пустое поле перетаскивается мышью/одним касанием; Space+drag допускает начало над карточкой. Колесо перемещает обзор, Ctrl/⌘+колесо масштабирует вокруг указателя. Стрелки (Shift — быстрее), +/−, 0 — вместить, 1 — 100% действуют только при фокусе самого поля. Ввод, кнопки и системные комбинации сохраняют свои действия. Tab показывает реальный фокус карточки и сдвигает камеру, если карточка вне экрана. Фокус не заперт. Esc, blur и pointercancel освобождают жест.

Кнопки масштаба и панели настроек закреплены вне сцены. Фон темы по умолчанию, пользовательский непрозрачный sRGB цвет, узор none/dots/grid. Настройки и камера локальны для пространства; отказ localStorage не ломает доску. Цвет фона не меняет семантическую палитру карточек. Узоры рисуются CSS без растров/анимации. Один rAF на пакет движений, отложенная запись настроек и обязательный dispose; нет idle-loop. Не заявлять поддержку нативного pinch всех ОС или точный retained heap по DOM-замеру.


## Render-window

**Когда применять render-window.** Для длинных лент, галерей и тяжёлых превью сначала рассмотрите `createRenderWindow` (`render-window`, core0.9.0+). Он создаёт owned subtree рядом с viewport/scroll-root, а вне экрана вызывает snapshot/dispose и оставляет лёгкий placeholder. Это рекомендация по сценарию, не обязательная обёртка каждой кнопки.

**Контракт интеграции.** Передайте фабрику `render(saved) => {element, dispose, snapshot?}`. Модель данных хранится у хоста; снимок ограничен и не удерживает DOM. В dispose освобождайте свои RAF, таймеры, подписки, observers, iframe и media. Сохраняйте высоту, фокус и незавершённый ввод; удерживайте выбранный/перетаскиваемый экземпляр через setPinned. Витрина ag-design уже использует эту обёртку: повторное оборачивание не требуется. Изменённые сложные примеры без явного snapshot/restore остаются закреплёнными, чтобы не сбросить их состояние.

**Когда выбрать другое.** Для маленького статичного блока достаточно обычного DOM. Основной текст документа, печать, SSR/SEO и поиск браузером требуют доступного eager содержимого либо отдельно проверенного режима. Для миллионов строк нужна также пагинация/виртуализация данных: placeholders и данные хоста остаются O(n). `content-visibility` может пропускать layout/paint при сохранении DOM, но не заменяет контракт освобождения ресурсов. Без IntersectionObserver у render-window eager fallback.

**Проверка до интеграции.** Сравните число живых экземпляров, DOM и owned ресурсов до/после прокрутки; проверьте повторный вход, snapshot, focus/keyboard/drag, смену страницы, темы и dispose. Измеряйте на целевом браузере. Node/jsdom и синтетические счётчики не являются процентом снижения CPU, retained browser heap или native RSS; неизвестное сохраняйте unknown.
