# Components and contextual review

[Русский](Components-and-review-ru.md) · [Home](Home.md)

Start from the user's task. Inspect purpose, anatomy, state ownership, lifecycle, versions and limitations before reuse. Atomic Design is an optional way to navigate elements, compound patterns, sections, templates and populated screens; it does not require five folders or five wrappers.

Keep shared structure separate from representative fixture data. Review long labels, unequal hints, empty/one/many results, loading/error/retry and pending actions where relevant. A child PASS does not qualify a whole screen. Record known dependencies and affected contexts; usage registrations are not a complete impact graph.

Read the current `form-row-layout` and `component-width-audit` chapters. Measure actual field tracks, root widths AND inner text columns. The AG width matrix is `normal`, `narrow`, `text200`, `narrow-text200`; use actual viewport/font evidence rather than a mode label. Keep the existing revision-bound changed-block inventory and inspect unchecked cases before completion.

Select local grids by purpose. Golden Canon/cinematic/photo grids support composition; form tracks and operational grids serve controls/data. Preserve content order and the host's chosen feed layout. Numeric grid fit cannot establish optical balance, contrast, keyboard/AT or security.

Generated palettes are candidates; preserve semantic roles and check actual foreground/background pairs. A failed mandatory contrast result cannot be averaged away. Functional, lifecycle, browser, accessibility and target-host checks remain distinct.
