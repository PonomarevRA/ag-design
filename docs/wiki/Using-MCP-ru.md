# Агенты и MCP

[English](Using-MCP.md) · [Главная](Home-ru.md)

1. Узнайте реальные инструменты и прочитайте `design_status`.
2. Перед компонентом вызовите `design_brief`, сохраните текущие версию и hash политики.
3. Ищите по назначению через `design_search`, затем читайте `design_component`. Пустое точное совпадение не доказывает отсутствие основы.
4. Найдите главу через `design_rule_sections`, прочитайте её через `design_rule_section`; для задачи/этапа/платформы используйте `design_recommendations`. Пример: `Atomic Design` и глава `atomic-design-composition`.
5. Переиспользуйте реальные фабрики и варианты, сохраняя семантику и палитру хоста.
6. Проверьте реальные состояния и контексты; передайте актуальные наблюдения и разберите unknown/unchecked. Числа геометрии не исполняют клавиатурный сценарий или AT.

В песочнице используйте объявленные операции композиции, document/revision/pins и idempotency keys. Описательный JSON-рецепт не является аргументами API. Подробности загружаются по запросу при стабильных схемах MCP.

Установщик добавляет навык по явному выбору. Фрагмент MCP подключается с сохранением существующих серверов/настроек; после установки нужен reconnect.

## Правила для Figma

Найдите «Figma» или «Фигма» через `design_rule_sections` и откройте `design_rule_section(section_id="figma-design-workflow", locale="ru", audience="user")`. Для этапа работы используйте `design_recommendations(query="Figma", stage="layout")`. Глава переводит действующие правила ag-design в операции над фреймами, компонентами и переменными Figma. Её можно открыть и в справочнике.

## Приватные каталоги проектов

Перед созданием интерфейса агент вызывает `design_project_components(project_id="demo-project")` и проверяет, есть ли подходящий компонент. После реализации сохраняет назначение, места использования, состояния и связи с общими компонентами через `design_save_project_component`. Пример записи:

```json
{
  "project_id": "demo-project",
  "component_id": "project-settings-form",
  "title": "Настройки проекта",
  "purpose": "Изменение имени и видимости проекта",
  "locations": ["settings/project"],
  "states": ["default", "saving", "error"]
}
```

Для чтения деталей добавьте `component_id` к запросу каталога. Для изменений и `design_remove_project_component` передавайте `expected_revision` из ответа. Для новой записи ревизию опустите.

Записи хранятся в рабочей SQLite-базе ag-design. По умолчанию она находится в каталоге данных пользователя вне checkout. Общий поиск, публикация репозитория и счётчики использования читают свои источники. `project_id` разделяет записи логически. Доступ к любому каталогу есть у клиентов, которым открыт тот же локальный MCP. Код компонента и файлы остаются в проекте.

## Обновления приложения

В конце задачи, где использовался ag-design, можно один раз вызвать `design_claim_update_reminder`. Если метод вернул новую версию, добавьте в конец ответа короткую подсказку со ссылкой и изменениями из changelog. Пустой ответ или ошибка не влияют на итог задачи. Следующее напоминание доступно через три дня. Для чтения кеша без отметки напоминания есть `design_update_status`.
