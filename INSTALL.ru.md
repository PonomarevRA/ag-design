# Установка

[English](INSTALL.md)

Все команды выполняются из папки скачанного репозитория. Нужны Python 3.11+, Node 22+ и npm. Установка скачивает заявленные зависимости из настроенных реестров. После подготовки комплектные ресурсы каталога работают локально.

## Нативные установщики

Выберите установщик своей ОС в [GitHub Releases](https://github.com/PonomarevRA/ag-design/releases/latest). Для macOS есть отдельные DMG для Apple Silicon и Intel. Для Windows x64 нужен WebView2. На Linux x64 распакуйте архив и запустите `Setup` в графической сессии. Установщик предложит отдельные папки приложения, данных и резервных копий. Сверьте загрузку с `SHA256SUMS`. Сборки macOS подписаны ad-hoc и не нотарифицированы Apple. Установщики Windows выпускаются без подписи.


## Автоматически

```sh
python3 tools/install.py --agent codex
```

В PowerShell замените `python3` на `py -3`. Укажите свой клиент: `codex`, `cursor` или `claude`. Без `--agent` устанавливается только приложение. `--dry-run` показывает пути без записи. `--skill-only --agent codex` устанавливает только навык. `--scope project --project /путь/к/проекту` выбирает проектный навык вместо пользовательского.

Создаётся `.venv`, устанавливается текущий checkout через pip, выполняются `npm ci --ignore-scripts` и сборка локальных архивов. Чужой отличающийся навык и неполная существующая `.venv` не перезаписываются. При конфликте выберите проектную область или сначала проверьте существующую установку.

## Вручную: macOS / Linux

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e .
npm ci --ignore-scripts
npm run build
.venv/bin/python -m ag_design
```

## Вручную: Windows PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
npm ci --ignore-scripts
npm run build
.\.venv\Scripts\python.exe -m ag_design
```

Откройте адрес loopback из вывода приложения. Команда запускает веб-версию. Для desktop из исходников установите `'.[desktop]'` вместо `.` и запустите `-m ag_design --desktop`. Linux desktop требует графическую сессию и системные библиотеки Qt/WebEngine; при их отсутствии используйте веб-режим. Эти команды не создают нативные установщики и подпись приложения.

## MCP и навык агента

Сначала запустите приложение из той же `.venv`. Затем добавьте MCP-сервер с абсолютным путём к `.venv/bin/python` (Windows: `.venv\Scripts\python.exe`), аргументами `["-m","ag_design","--mcp"]`. Автоматическая установка формирует готовый фрагмент `.ag-design/mcp.json`. Объедините его с настройками своего клиента, сохранив остальные серверы. После переподключения вызовите `design_status` и проверьте фактические версию и число компонентов. Запись MCP сама по себе не запускает HTTP-приложение.

Навык находится в `skills/ag-design`. Пользовательские пути: `~/.codex/skills/ag-design`, `~/.cursor/skills/ag-design`, `~/.claude/skills/ag-design`. В проектной области Codex использует `.agents/skills/ag-design`, остальные клиенты — свою папку. Для обнаружения навыка может понадобиться новый сеанс.

Git не требуется для ZIP-поставки. В клоне локальную проверку перед push включает `git config --local core.hooksPath .githooks`; автоматический установщик делает это только внутри Git checkout. Проверка читает индекс и историю, не отправляя и не меняя данные.


## Необязательный локальный смысловой поиск

Установите `python -m pip install -e ".[search]"`, явно выполните `python tools/setup-search-model.py`, затем перезапустите сервис и переподключите MCP. Веса хранятся во внешнем кеше; поисковые запросы не загружают модель и не отправляют текст внешнему embedding API. Без модели/runtime остаются FTS5 и точные результаты. `AG_DESIGN_SEARCH_MODE=fts` отключает модель. `design_discover` возвращает кандидатов для проверки, а не автоматический допуск.
