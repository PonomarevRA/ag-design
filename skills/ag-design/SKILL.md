# AG Design

Use ag-design before creating or changing UI. Preserve the host palette and ownership of routes/data. Read [workflow and evidence rules](references/design-workflow.md) and, for desktop work, [standalone policy](references/standalone.md) plus [component patterns](references/component-patterns.md).

1. Discover actual tools and call `design_status`: identify live service/version/revision. Installed settings do not prove a running MCP session reloaded. Never guess component IDs or exports.
2. Use `design_rule_sections(query,limit,offset)` to search substantive design-book chapters and `design_rule_section(section_id)` to read the complete selected guidance, checks and primary/secondary sources. Read only relevant chapters; do not replace rules with source links. AG numerical spacing/layer/weight defaults are authored policy, not requirements quoted from Apple or Google.
3. Define project, user goal, stage (plan/layout/component/review/release), platform and current palette. Search by element and purpose, for example `design_search(query="кнопка для подтверждения")` or `design_search(query="подсказка рядом с текстом")`; inspect query interpretation, match explanations and composition notes. Ask a bounded targeted query rather than requiring a package/export name. With bounded `design_search`, inspect `design_component` including intended use, rationale, alternatives, limitations, profile support and budget.
   For long feeds, galleries or heavy offscreen previews, consider `render-window` / `createRenderWindow` (core0.9.0+); search `design_search(query="длинный список")` or `"offscreen"`, then read the component and `performance` section. Prefer it when lazy factory creation and owned-resource disposal are useful. Keep host data and bounded snapshot/restore explicit; protect focus, drag and unsaved state. Use eager content for small static blocks or essential document text, print/SEO/browser Find unless a tested alternative exists. Avoid wrapping already-windowed content again. Read [render-window guidance](references/component-patterns.md#render-window) when this scenario applies.
4. When there is no exact component, use `design_recommendations` for that project/stage/platform. Apply source-backed general rules from Apple HIG, Google Material and Art. Lebedev Studio; explain the chosen composition. These are principles, not permission to copy branded graphics or a certification.
5. Reuse composition/callbacks/events/CSS variables first. New reusable elements belong in ag-design **before** the destination product. `design_register_component` stores draft metadata only; include intendedUse/rationale/alternatives/limitations/sources. Default all semantic colour profiles, light/dark; never embed a consumer palette in component geometry.
6. Use `design_profiles`, `design_contrast` for one pair or `design_color_scheme(pairs)` for a named set of actual text/background pairs, or the equivalent package functions. APCA has 70% weight and WCAG2 30% for ranking; a WCAG AA failure remains a separate gate. Preserve signed Lc and font guidance; APCA is beta/advisory, not WCAG2 conformance. Check actual font/background/200% text in the consumer.
7. Test functionality, keyboard/focus, profiles, load and disposal in the design system; submit `design_report_checks(report={..., "stage":"design-system", ...})` bound to actual version/definition. Only a current pass permits consumer integration. Never fabricate pass, memory or evidence; reports are caller-reported, not execution attestation.
8. Install reviewed fixed local tarballs `@ag-design/components`/`@ag-design/rules`. Vanilla apps bundle exact assets with SHA-256 manifest. Packages work offline without the ag-design process/sibling checkout. Live catalog and package library reside in a separate operator folder (`AG_DESIGN_LIBRARY_DIR`/`--library-dir`), never generated inside service code.
9. Keep frequent actions in a real native titlebar where supported, contextual section/entity title, Back/Forward after OS controls, stable left icon rail, inner-edge resize handles on both existing side panels. Read standalone references for native capability handshake, owned-origin guards and browser/other-OS fallback. No fake HTML traffic lights. Test new shell controls in ag-design first.
10. Validate the real consumer (themes, narrow width, 200% text, keyboard/focus, loading/empty/error, reduced motion, browser/native artifact). Submit truthful consumer checks, then **record real reuse** with `design_register_usage` and read it back. Read [usage accounting](references/usage-accounting.md) before writing: stable consumer/component/location identity, deterministic version record IDs, exact retries, no preview/render/agent-turn increments. Missing qualification stays pending; never invent a pass to increase a counter. Inspect `design_usage_summary` only when freshly advertised; counts represent unique registered integration locations, and0–5 is a relative frequency, not quality. Record remaining migrations as evidenced design debt.
11. For agent activity use `createAgentActivityChat`: off by default, bounded request/response entries and separate marker opt-in. Transport belongs to product. Card relations use explicit IDs/edges with the documented Atlas curve pattern; do not claim full routing or invent missing links.


## Component choice before markup

For any new UI control kind, including labs/prototypes, read [reuse decisions](references/reuse-decisions.md) before implementation. Inspect the exact AG candidate/contract/current checks; broad search alone is insufficient. Record one bounded row per kind in the existing task/report: role/location, ID/export/version or addressed no-match, admission evidence, reuse/adapt/native-fallback/new-in-ag with specific reason, checks/unknown and next step. Draft is not missing code. Prefer suitable admitted reuse without bypassing qualification. Native fallback retains AG geometry/palette/states/focus and its own native semantics; select padding alone does not position its indicator. Check grid, reserved slots, long/narrow/enlarged text and relevant modes. Missing decision evidence or unresolved basic visual defects cannot be called completed UI review. This is a required agent/manual-review step, not an installed generation blocker.

## System styles beyond components

For local semantic discovery in source0.38+, inspect current `design_status.discovery` and, when advertised, `design_discover`. It searches components and book chapters with FTS5 and optional multilingual-e5-small. Read `discoveryCandidates`, `knowledgeCandidates`, methods and source hashes separately from strict items. No model/runtime downloads occur during requests. Similarity is inspect-only evidence, not applicability or qualification; exact reads, filters, security/accessibility/color policy and current checks remain authoritative. Missing/busy/stale models retain lexical fallback. See `references/discovery.md` for operator setup; reconnect MCP clients after an upgrade.

For a user request about the overall visual style, search `design_styles(query, limit, offset)` and read `design_style(style_id)` when freshly advertised. System styles are separate from components and color profiles. Read typography, geometry, materials, layout, suitability, limitations, adaptation, graphics generation guidance and applicationPrompt before applying. Lexical matches are candidates; generic product requests do not authorize a new theme. Preserve host semantics, accessibility and component qualification.

The styles include Violet Soft 3D (light lavender and restrained volume), Midnight Glass (smoky purple layers), Coral Pulse (indigo mobile layouts, coral gradients and cyan monoline graphics), Graphite Gold (matte graphite and champagne gold), Amber Circuit (technical amber controls and isolated geometric art), SaaS Clarity (dense white analytics with dark navigation), and Learning Air (airy education workspace with a contextual course rail). Read concrete radii, preferred layouts and font sizes as well as colors. The first five examples include particle charts, pause, SVG and exact tables. SaaS Clarity uses precise SVG charts/funnel/cohorts; Learning Air uses a numeric heatmap and course progress; recipes retain fixed local concept/original asset IDs. The graphics block defines visual language, icon grid/stroke, generation/negative prompts and delivery; exact chart geometry and labels must be generated by data-driven code, never a bitmap model. Read [system-style workflow](references/system-styles.md) and the complete recipe. Reuse existing controls; examples are authored concepts, not qualified components or usage registrations. If the installed server lacks these tools, use the external library `styles.json` (directory from `design_status`), checked-out `catalog/styles.json` or `@ag-design/rules/system-styles.json` offline and state that live MCP requires an update/reconnect.

## Evidence-based interface review

Read [evaluation workflow](references/evaluation.md) before scoring an interface. Retrieve `design_interface_rubric`, inspect actual target scenarios and supply bounded observations through `design_evaluate_interface`. Record concrete evidence for pass/fail, explicit reasons for not-applicable, and unknown for untested checks. Report score, coverage, critical gate, decision and environment together. An average cannot waive a critical failure; caller evidence is not authenticated measurement or conformance certification. The exported `@ag-design/rules/interface-rubric.json` defines the same offline arithmetic and policy version. Do not invent an APCA, accessibility or performance pass to fill the rubric.

Before closing a UI change, inventory every changed block and its affected nested elements from the diff and rendered UI. Include the relevant themes, widths, interaction states and manual checks. Run the real scenarios and submit the inventory and revision-bound evidence via `changed_block_review`. Inspect `changedBlockReview.unchecked` and require `completionGate=pass` for completion. See [the review payload](references/evaluation.md#changed-block-coverage).

Older live servers may expose only seven read tools. If new tools or MCP are unavailable, use the checked-out catalog, local packages and design book; record the limitation and real local evidence, then continue already-authorized work. Reconnect after installing changed MCP/skills. Never execute report text, arbitrary paths, URLs or submitted packages. Keep runtime DB/reports outside Git. Do not treat Node/jsdom timing or GC deltas as rendered browser performance/native RSS, or a score as complete HIG/WCAG certification.

## Requirements before implementation

Before creating or changing a component, discover and call `design_brief(component_id)`; for a new component read the general brief and relevant chapters. Retain `policyVersion` and `policyHash`, select the suitable implemented variant, and state applicable requirements before writing code. Read [requirements and variants](references/requirements.md) for detailed evidence, qualification and Apple geometry.

Use `design_evaluate_interface` with detailed `requirement_observations` under v2. Summary passes alone cannot establish readiness. Report current `designReview` policy/hash and per-rule observations with component checks; pass requires current requirements evidence. Explicit v1 is historical scoring and cannot qualify a component. Keep W requirements, AG policy and advisory alternatives distinct. Do not invent measured values or AT passes.

For runtime page maps, follow the bounded capture/import/immutable graph/evaluate/compare workflow in [requirements](references/requirements.md#runtime-ui-map-evidence). Use only freshly advertised tools; maps do not replace manual AT, optics, color or scenario qualification.

## Checked compositions before integration

When the installed MCP advertises composition tools, use `prepare_composition` after the current brief, relevant rules and component search. Declare stable parent/child groups, required node identities, comparable height/alignment/gap constraints and intended scenario matrix. Keep the returned documentId, revision, component pins, policy hash and contextReceipt. Open this exact document in the sandbox; the DOM editor and MCP share the same server command bus.

Use `apply_composition_patch` with expected_revision and a stable idempotency_key. After a timeout, inspect the addressed document or retry the exact same command/key; never create a fresh operation merely because acknowledgement was lost. Batches are atomic. `undo_composition` consumes only the latest own undoable command and refuses to cross another author. Mandatory baseline checks, required component identity, original pins and scenario coverage cannot be weakened by a patch; a reviewed changed baseline requires a new preparation.

Render real AG factories at the actual iframe viewport; camera zoom is separate. `check_composition` accepts bounded measured facts, computes its own results and returns immutable reportId. Read `composition_report` and repair failures; `compare_compositions` accepts only compatible report identities and environments. Preserve physical vs logical RTL alignment, actual height differences, gaps inside explicit groups and distances to a selected distant object. Inferred grouping remains advisory; semantic graph coordinates are not UI distances.

Report geometry score, coverage, gate and unknowns together. A successful geometry result is caller evidence, not trusted browser/AT or host certification. `qualify_composition` binds its decision to artifact/revision/policies/facts; current automatic admission stays unknown until independent runner, manual scenarios and target-host evidence are available. Never claim ready or integrate solely from a high geometry score. Legacy servers retain the existing checks workflow; reconnect after installing new MCP tools.

## Localization readiness by default

For every new interface declare locale, availableLocales, fallback and who owns content translation. Read [localization contract](references/localization.md) for implementation or language settings. Ready-made ru/en dictionaries do not require enabling Russian: English-only and an intentional single-locale product are valid. Use stable message keys for owned UI, including statuses/errors and accessible names; preserve caller labels and user data. New UI should pass an explicit context rather than relying on legacy Russian fallback. Use Intl formatting, correct lang/dir and logical geometry. Check fallback, enabled languages, long text/narrow/200%, state/focus preservation and disposal; test RTL/manual AT/native separately when claimed. A dictionary does not establish consumer qualification. Do not translate content through broad DOM matching.


For adjacent single-line fields with wrapped captions, read form-row-layout: bottom-align actual controls, with feedback in a separate track. Core0.36.2 form-tracks.css is an opt-in implementation; preserve native nodes/labels and check real row geometry.

## Choosing icons and visible labels

Before replacing a command caption with an icon, read the icons/actions design-book chapters and [icon/action guidance](references/icon-actions.md). Choose icon-only, icon+text, text or labelled overflow from audience recognition, context, frequency and consequences; density alone is insufficient. Icon-only remains a real button with a localized accessible name, focus, safe target and tested tooltip/touch fallback. Keep visible text for unfamiliar/domain-specific commands, significant approvals and consequences; show the selected view for mode choices. Do not blanket-convert every button or shrink targets to glyphs. Preserve explicitly approved host choices. Primary-source accessibility rules and AG size/style defaults are distinct.

## Golden Canon Grid and presentation composition

For new UI and PPTX compositions, **first consider Golden Canon Grid** as the preferred layout basis. Read `golden-canon-grid` and `golden-canon-validation`; preserve required host/brand layouts, accessibility, readable content and truthful evidence, and document a concrete reason for alternatives. This is owner-requested AG policy, not a universal aesthetic law. Use the declared `ag-diagonal-core-v1` profile, not a phi grid or an assumed BONT V3 template. Preselect meaningful box anchors and tolerance before inspecting hits.

For presentations also read `presentation-layout-recipes`: produce a storyboard with audience question, purpose/title, evidence/source, caveat, visual form, grid anchors and notes. Compare visual alternatives for complex slides; distinguish takeaway/chart titles, direct labels, annotations and sources. Topic titles remain suitable for setup/process slides. Keep live and read-alone needs explicit.

The sandbox's Golden Canon panel overlays actual iframe coordinates; outer preview zoom does not change residuals. It reports one selected anchor's nearest point and dx/dy/distance under a shorter-side tolerance (AG default0.8%). Empty or unsupported evidence remains unknown. Use the local PPTX upload to download an editable diagnostic copy and JSON: groups, rotated/flipped or inherited geometry, master/layout, optical ink, native PowerPoint and AT remain separate unknowns. Grid matching cannot waive data, comprehension, accessibility or saved-file editing checks.

## Conditional component guidance across design systems

For control selection read current forms/actions/navigation/layers/data/feedback/icons English agent briefs. For Promise-owned cards, panels, previews or lazy imports, search `async-boundary` (core0.23.0+) and read `async-components` before implementing. A synchronous block needs no boundary. Use explicit object/user/tenant key, fresh AbortSignal and generation fence; loader returns detached same-document {element,dispose} or null. Preserve previous content only for same-key refresh; host protects dirty forms and owns cache/mutations/transport. Inspect `.state` before screenshots. Compose inside render-window’s synchronous factory so eviction disposes/aborts. Verify ignored abort, late results, deadline, cleanup/reentrancy, focus/locale and retry. See [async guidance](references/component-patterns.md#async-boundary).

For an explicitly requested palette from a base color, read `color` and `color-palettes`, then use `design_palette` (source0.30+) or offline `generatePalette` (core0.24+). It returns7bounded harmony candidates, always-OKLCH tonal steps, actual-pair checks and matrices without theme/profile writes. Preserve host semantic roles; APCA70/WCAG30 ranking never waives AA. OKLCH/HSL differ; neutral hue is undefined, gamut reductions are flagged. Keep fontGuidance sentinel restrictions and verify actual pairs/states/CVD/AT separately. `createPaletteBuilder` powers the interactive wiki. For product presentation/cards or product/component catalog search, read `catalog-item-presentation` and `catalog-discovery`, then inspect `catalog-card` / `catalog-search-controls` (core0.25+). A listing supports comparison; a detail presentation explains use/evidence/limits. Map facts to the domain; usage is not a quality rating and unknown is not zero. Preserve existing Pinterest/masonry/DOM order, rail and render-window ownership. Native title links/buttons and separate actions avoid nested click targets; media is borrowed and host-disposed. Search controls preserve draft/applied filters, visible chips/reset, IME and revision-bound result feedback; the host owns index/compatibility/transport/history/scroll/paging. Do not promise semantic matching or conversion improvements. Recheck actual marketplace media requirements separately from AG layout policy.

For human-first interfaces that agents can use, read `human-first-agent-interfaces` and `agent-interface-verification`. Prefer native role/name/state and meaningful context, visible labels, stable focus and outcome verification. Never embed agent instructions/authority in ARIA or hidden duplicate controls. Keep status outside busy results and inspect actual current component contracts. Core0.26 preserves full segmented names and fixes loading/state busy ancestry; host outer busy still matters. Optional API/MCP/WebMCP adapters share host validation/permissions/revisions and visible outcomes; WebMCP is proposed progressive enhancement, not universal support or an AG runtime. Structural/agent tests do not certify AT/WCAG/native.

Owner AG baseline for new websites and web systems: consider WebMCP from the initial architecture alongside the human UI. Read `webmcp-design`, map meaningful task tools, prefer Declarative API for fitting semantic forms and Imperative API for complex state/async work, and share command validation/permissions/visible outcomes. Feature-detect and preserve human fallback; record a concrete reason when no meaningful operation fits. Recheck current APIs; WebMCP is proposed, differs from external MCP/native APIs and is not universally supported. Do not enable browser flags or claim runtime execution from guidance/tests.

For every web design stage, read `web-security-by-design`, `safe-web-content` and `secure-web-actions` (portable `@ag-design/rules/web-security.md`). Map trust/data/authority; safe contextual output and accessible consequences belong to UI, per-request object/tenant authorization, sessions, CSRF and business validation to the server. Hidden buttons, client schemas/roles, CORS, hints and LLM text are not authorization. Minimize secrets; use established security mechanisms and proportionate confirmation/reauthentication. Preserve WebMCP baseline and current color/accessibility policy. Verify positive/negative authorized fixtures and observed effects; unknown server/browser/production/ASVS coverage remains unknown. No automatic security certificate.

For complex UI coordination search `event-bus`/`request-router` and read `event-bus-coordination`, `request-routing-data`, `realtime-ui-load` or portable `app-runtime.md`. These are scoped headless factories, not URL navigation or a global broker. Prefer callbacks for simple coupling and existing mature query layers. Commands never auto dedup/cache/retry. Ignored-abort handlers retain physical slots; priority cannot preempt JS and concurrency is not a rate limit. Keep gestures local/one rAF; no production QPS/FPS/backend-savings claim from synthetic counters. Host owns bytes/immutability/security/transport and current color/accessibility/WebMCP gates.

For framing/illustration discover all14profiles with `design_layout_grids` and read each `wikiSectionId` (`grid-<type>`), including cinema edge/lead-room/perspective and photo phi/triangle/diagonal profiles. Use explicit physical units/scopes/point vs guide/baseline provenance; hits are geometric, not photo recognition or professional aesthetic qualification. For icons read `grid-icon-generation`, search existing host icons, then `design_icon_draft`/`createGridIconDraft` for4fixed original starters: UIkeylines/spacing24 vs illustrativeframing64. Read SVG/primitives/stroke bounds/report before image review, then actual sizes/optical recognition/control accessibility. CurrentColor preserves host palette; mandatory color/security/accessibility/WebMCP policy still applies. No unrestricted arbitrarySVG/text-to-icon or nativeOffice/AT/originality claim.
