# Required component checks

1. Find the exact ID/version/contract; inspect the existing component tests and actual library sample.
2. Execute targeted unit/lifecycle tests plus `node --test tests/performance-runner.test.mjs` for core previews. The latter exercises every registered core preview and fails on missing interactions or cleanup. Connected libraries execute their own package scenarios. Add meaningful component regressions with the change.
3. Exercise a relevant actual-browser scenario in ag-design; select the component on Performance rather than run every component unnecessarily. Test failed interaction/cleanup and cancellation in regressions. Preserve unknown browser/AT evidence when unavailable.
4. Where retained JS memory matters: `node --expose-gc tools/benchmark-memory.mjs --component ID --instances 40 --output /absolute/path/report.json`. Explicit GC and jsdom model shims are not real browser layout, native RSS, GPU or complete leak evidence. Keep a negative median unavailable.
5. Submit each executed record through freshly advertised `design_record_performance(report)` and read `design_performance`. Records require component ID/version, scenario, environment and bounded finite metrics. `outcome=failed` requires error phase/message and may have no metrics; cancelled is separate. Do not change failure to measured or fill missing values with zero. The tool stores caller evidence, never runs submitted code. Qualification independently uses current `design_report_checks`; a performance row is not admission.
6. Report exact commands/results, saved record IDs, environment/limits and remaining unknowns. If the new tool is not available in an older MCP client, reconnect; retain a bounded report outside Git meanwhile. Never bypass guards or claim a test ran merely because it was registered.
