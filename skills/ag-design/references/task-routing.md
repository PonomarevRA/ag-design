# Task routes

Use only the rows that apply to the task, then the named local reference or current MCP chapters. The design book owns detailed rules and supported capabilities; this index is not a second policy book. Chapter names below are `design_rule_section` IDs, not commands. If a chapter/tool is absent, use matching offline rules and report the fallback.

| Task | Read or discover when needed |
| --- | --- |
| Forms, adjacent fields, search/filter bands | `form-row-layout`, `component-width-audit`; [management controls](management-controls.md). Declare semantic groups and label/control/feedback tracks; stack by available width, then measure controls and inner columns. |
| Grids, illustration or icons | `golden-canon-grid`, `golden-canon-validation`, `layout-grid-selection`, `nested-layout-grids`, `layout-grid-inspection`; inspect `design_layout_grids` before choosing profiles. Golden Canon is the preferred creative starting point, not a phi grid. Use suitable columns/modular/reading grids by scope. For icon drafting read `grid-icon-generation` and [icon actions](icon-actions.md). |
| Composite components, page templates, sandbox or UI maps | `atomic-design-composition`; [requirements](requirements.md). Child qualification does not qualify the full screen. Keep component pins, ownership, explicit groups and exact document/revision identities. |
| Async content, large feeds or component coordination | [component patterns](component-patterns.md); `async-components`, `performance`, `event-bus-coordination`, `request-routing-data`, `realtime-ui-load` as applicable. Search async-boundary/render-window/event-bus/request-router by purpose; do not introduce them for simple synchronous blocks. |
| Overall style, visual interest or branding | Search `design_styles` then read the selected `design_style`; [system styles](system-styles.md). For branding use `creative-direction`, `brand-book`, `design-system-governance`; for a technique search its chapter, e.g. `mesh-gradients` or `visual-interest-techniques`. A generic request does not authorize changing the theme. |
| Color selection and palettes | `color`, `color-palettes`; inspect `design_palette` candidates and actual-pair contrast. Preserve semantic roles; harmony/ranking never waives AA. Color/evaluation details: [evaluation](evaluation.md). |
| Catalog cards, sorting, popovers or compact switching | `catalog-item-presentation`, `catalog-discovery`, `list-view-controls`, `nonmodal-popovers`, `gitlab-pajamas-patterns`; inspect actual catalog-card, catalog-search-controls, sorting-control, choice-chips and popover contracts. Preserve host Pinterest/masonry order. |
| Human-first web UI and agent adapters | `human-first-agent-interfaces`, `agent-interface-verification`, `webmcp-design`; for web stages read `web-security-by-design`, `safe-web-content`, `secure-web-actions`. Share host validation/permissions and visible outcomes; feature-detect WebMCP and preserve human fallback. |
| Desktop shell or command placement | [Standalone policy](standalone.md), [window versus component commands](window-command-placement.md), [icon actions](icon-actions.md). Native capabilities and browser fallback need separate evidence; no imitation OS chrome. |
| Native assistants | [Native assistant guidance](native-assistants.md); `assistant-action-contract`, `native-assistant-overview`, then the target platform and `assistant-integration-testing`. Research, implemented adapter, discovery and real invocation are separate states. |
| ChatGPT/MCP Apps, ChatKit or chat presentations | [Conversational UI](openai-ui.md); read the target host contract before integration. Host-specific restrictions do not override ordinary website palettes/layouts. |
| PPTX, Excel or data narratives | [Artifact workflow](artifact-workflow.md). Route to the available format-specific producer; verify editable output, rendering, data and accessibility separately from web qualification. |
| Brand boards or customer-journey prototypes | Discover `design_studio_contract`; read `customer-journey-prototype`, `brand-interchange`, `journey-testing-retention`. Use exact-revision compositions and the Studio command bus. Temporary tests stay temporary; do not silently recreate an ambiguous create or extend retention with keepalives. |
| Figma design or handoff | Read `figma-design-workflow` via the current book. Apply AG grid, form, state, token and review rules to frames and instances. Verify runtime behavior in the implementation. |
| Project-specific components | Use the exact agreed `project_id`. Read `design_project_components` before authoring. Save reusable metadata with `design_save_project_component` and read it back. Keep shared AG references in `base_component_ids`; carry the returned revision into edits. |
| Locale, translation or book authoring | [Localization](localization.md); [book language contract](book-language-contract.md) when selecting audience/locale or editing the book. MCP defaults to compact English agent guidance; single-locale products are valid. |
| Search misses or unavailable semantic model | [Discovery](discovery.md). Inspect lexical versus discovery candidates, hashes and runtime status; missing models retain lexical fallback. Do not download/enable runtimes merely to hide a no-match. |

For broader lifecycle/offline-package mechanics, read [design workflow](design-workflow.md) only when those mechanics are part of the task. Do not load every linked reference on entry.
